# /onepager — the window on a single page

Render one date window as a single dense page: the glance level of the
story, on paper. This is the default collateral brag produces via Marp —
never a multi-slide deck. Marp ships in the brag package, so `marp` is on
PATH wherever brag is.

1. Window from the arguments; if absent, ask. Read it:
   `brag read --from <from> --to <to>`.
2. Cluster and rank exactly as `/report` does; if a report for this window
   exists in `reports/`, reuse its themes and order — page and report must
   tell the same story. Reviews-style supporting work is listed last.
3. Write `reports/<from>--<to>.onepager.md`: Marp frontmatter with
   `marp: true` and a `style:` block that sets `section` to portrait page
   dimensions (`width: 794px; height: 1123px`, tightened padding, small
   base type ~15px). ONE page only — if it overflows, cut evidence bullets
   before shrinking type below readable:
   - header line: ledger name · window · owner
   - the one-line thesis
   - the headline numbers on one row
   - per theme: the claim in bold, one supporting line, the `repo#ids`
   - the kudos, quoted verbatim and attributed, one or two lines
   - footer: generated by brag
4. Render: `marp reports/<w>.onepager.md --pdf --allow-local-files -o
reports/<w>.onepager.pdf`. PDF export needs a Chrome/Chromium/Edge on
   the machine (`CHROME_PATH` overrides); if none is found, fall back to
   HTML output and say so.
5. Verify it is actually one page (`pdfinfo` if present, or file size and
   a re-read of the markdown for overflow risk), commit both files, push
   if the data repo has a remote, and hand the user the PDF.

Done when the user has a one-page PDF telling the same story as the
window's report.
